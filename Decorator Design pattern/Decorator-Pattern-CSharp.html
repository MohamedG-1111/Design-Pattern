Decorator Pattern في C#

إزاي نضيف Logging وEncryption للـ Email وSMS من غير ما نكرر Classes أو نعدّل في الكلاسات الأصلية؟

1) المشكلة: انفجار عدد الـ Classes

تخيل إن عندنا نوعين لإرسال الإشعارات: EmailNotifier وSmsNotifier. وبعد كده احتجنا نضيف ميزتين:

  • Logging: نسجل إن عملية الإرسال حصلت، وممكن نسجل تفاصيل مناسبة عنها.
  • Encryption: نضيف خطوة تشفير للرسالة قبل إرسالها.

لو اعتمدنا على Inheritance وعملنا Class لكل تركيبة، هنحتاج Classes زي:

  • EmailWithLogging
  • EmailWithEncryption
  • EmailWithLoggingAndEncryption
  • ونكرر نفس التركيبات مع SMS.

كل ما نزود Feature جديدة، عدد التركيبات المحتملة بيزيد. وده بيعمل تكرار، وبيصعّب الصيانة والتعديل.

2) الحل: Decorator Pattern

بدل ما نعمل Class لكل تركيبة، بنعمل Decorator مستقل لكل Feature. كل Decorator بيستقبل Object بيطبّق نفس الـ Interface INotifier، ويضيف سلوكه، وبعدها يمرر التنفيذ للـ Object اللي جواه.

EmailNotifier / SmsNotifier←EncryptionDecorator←LoggingDecorator

الفكرة الأساسية: الـ Decorator نفسه بيطبّق INotifier، علشان نقدر نستخدمه مكان أي Notifier، ونلف Decorator حوالين Decorator تاني.

3) الكود الكامل

أولًا: الـ Interface الأساسي

public interface INotifier
{
    void Send(string message);
}

ده العقد المشترك. أي نوع Notification أو Decorator لازم يوفّر الدالة Send.

ثانيًا: الكلاسات الأصلية

public class EmailNotifier : INotifier
{
    public void Send(string message)
    {
        Console.WriteLine($"Sending Email: {message}");
    }
}

public class SmsNotifier : INotifier
{
    public void Send(string message)
    {
        Console.WriteLine($"Sending SMS: {message}");
    }
}

الكلاسات دي مسؤولة عن الإرسال الأساسي فقط. مش محتاجة تعرف أي حاجة عن Logging أو Encryption.

ثالثًا: Logging Decorator

public class LoggingDecorator : INotifier
{
    private readonly INotifier _notifier;

    public LoggingDecorator(INotifier notifier)
    {
        _notifier = notifier;
    }

    public void Send(string message)
    {
        Console.WriteLine("[LOG] Sending notification...");

        _notifier.Send(message);

        Console.WriteLine("[LOG] Notification process finished.");
    }
}

الـ Logging Decorator بياخد أي Object من نوع INotifier. قبل الإرسال وبعده بيطبع Log، وبعدين بيفوّض الإرسال للـ Object اللي جواه.

رابعًا: Encryption Decorator

public class EncryptionDecorator : INotifier
{
    private readonly INotifier _notifier;

    public EncryptionDecorator(INotifier notifier)
    {
        _notifier = notifier;
    }

    public void Send(string message)
    {
        string encryptedMessage = Convert.ToBase64String(
            System.Text.Encoding.UTF8.GetBytes(message)
        );

        Console.WriteLine("[ENCRYPTION] Message encrypted.");

        _notifier.Send(encryptedMessage);
    }
}

هنا بنحوّل الرسالة إلى Base64 كمثال توضيحي، وبعدها نمرر الناتج للـ Notifier اللي جوه الـ Decorator.

ملاحظة مهمة: Base64 مش تشفير آمن؛ ده Encoding فقط. في مشروع حقيقي استخدم خوارزمية تشفير موثوقة وإدارة مفاتيح مناسبة، أو اعتمد على تشفير قناة الاتصال مثل TLS حسب احتياج النظام.

خامسًا: تجربة التركيبات في Program.cs

public class Program
{
    public static void Main()
    {
        INotifier email = new EmailNotifier();

        INotifier emailWithLogging =
            new LoggingDecorator(email);

        INotifier emailWithEncryptionAndLogging =
            new LoggingDecorator(
                new EncryptionDecorator(
                    new EmailNotifier()
                )
            );

        INotifier smsWithLoggingAndEncryption =
            new LoggingDecorator(
                new EncryptionDecorator(
                    new SmsNotifier()
                )
            );

        Console.WriteLine("=== Email with Logging only ===");
        emailWithLogging.Send("Hello Mohamed");

        Console.WriteLine();

        Console.WriteLine("=== Email with Encryption and Logging ===");
        emailWithEncryptionAndLogging.Send("Hello Mohamed");

        Console.WriteLine();

        Console.WriteLine("=== SMS with Encryption and Logging ===");
        smsWithLoggingAndEncryption.Send("Your code is 1234");
    }
}

4) إيه اللي بيحصل وقت التنفيذ؟

لما ننفّذ السطر ده:

INotifier notifier =
    new LoggingDecorator(
        new EncryptionDecorator(
            new EmailNotifier()
        )
    );

notifier.Send("Hello");
  1. استدعاء Send يبدأ من LoggingDecorator.
  2. الـ Logging يطبع رسالة بداية العملية.
  3. ينادي EncryptionDecorator.Send.
  4. الـ Encryption يحوّل الرسالة إلى Base64.
  5. ينادي EmailNotifier.Send بالرسالة الناتجة.
  6. بعد رجوع التنفيذ، الـ Logging يطبع إن العملية انتهت.

يعني الترتيب هنا: Logging قبل الإرسال، ثم Encryption، ثم Email. ترتيب الـ Decorators مهم؛ لأن كل واحد بيضيف سلوكه في المكان اللي هو موجود فيه في السلسلة.

5) ليه Decorator أفضل هنا؟

  • إعادة استخدام: نفس Logging Decorator يشتغل مع Email أو SMS أو أي Notifier جديد.
  • تركيب مرن: تقدر تضيف Logging فقط، أو Encryption فقط، أو الاتنين.
  • من غير تعديل الأصل: مش محتاج تغيّر EmailNotifier أو SmsNotifier.
  • تقليل التكرار: كل Feature مكتوبة مرة واحدة في Decorator مستقل.

6) الخلاصة بالبلدي

اعتبر إن عندك جهاز أساسي، وكل Decorator عبارة عن طبقة بتضيف له إمكانيّة. تقدر تركّب طبقة Logging وطبقة Encryption فوق أي Notifier، وبأي ترتيب مناسب، من غير ما تعمل Class جديد لكل احتمال.

افتكر: Decorator = نفس الـ Interface + Object من نفس النوع + سلوك إضافي + تمرير التنفيذ للـ Object الداخلي.

مثال تعليمي باستخدام C# وConsole Application. يمكن وضع الكلاسات في ملفات منفصلة أو معًا داخل مشروع واحد.
