شرح Adapter Design Pattern

هنفهم الـ Adapter Pattern من الصفر وبالمصري: المشكلة اللي بيحلها، ليه بنحتاجه، مثال كامل بـ C#، وطريقة تنفيذ الكود خطوة خطوة.

1. يعني إيه Adapter؟

كلمة Adapter معناها «محوّل». زي محوّل الشاحن: عندك فيشة بشكل معيّن ومقبس بشكل مختلف، فبتستخدم قطعة في النص تخلي الاتنين يشتغلوا مع بعض.

في البرمجة الفكرة نفسها: ممكن يكون عندك كود في مشروعك متوقع يتعامل مع Interface معيّن، وتحتاج تستخدم كلاس جاهز أو مكتبة خارجية، لكن طريقة التعامل معاها مختلفة. بدل ما تغيّر نظامك كله أو تعدّل المكتبة الخارجية، بتعمل كلاس وسيط اسمه Adapter يحوّل طريقة النداء من الشكل اللي نظامك متوقعه للشكل اللي الكلاس الخارجي بيفهمه.

2. المشكلة اللي بنحلها

افترض إن عندنا نظام إشعارات، والنظام بتاعنا متفق إن أي وسيلة إرسال لازم تطبّق الـ Interface ده:

public interface INotifier
{
    void Send(string message);
}

يعني أي كلاس عايز يدخل نظام الإشعارات لازم يوفّر دالة اسمها Send وتستقبل رسالة نصية.

عندنا كلاس للإيميل وكلاس للـ SMS، والاتنين ملتزمين بالاتفاق:

public class EmailNotifier : INotifier
{
    public void Send(string message)
    {
        Console.WriteLine($"Sending Email: {message}");
    }
}

public class SmsNotifier : INotifier
{
    public void Send(string message)
    {
        Console.WriteLine($"Sending SMS: {message}");
    }
}

وعندنا كلاس مسؤول عن تشغيل الإشعارات. هو مش مهتم هتبعت Email ولا SMS؛ هو بيتعامل مع أي كائن من نوع INotifier:

public class NotificationManager
{
    private readonly INotifier _notifier;

    public NotificationManager(INotifier notifier)
    {
        _notifier = notifier;
    }

    public void Notify(string message)
    {
        _notifier.Send(message);
    }
}

لحد هنا الدنيا تمام. نقدر نستخدمه كده:

var emailManager = new NotificationManager(new EmailNotifier());
emailManager.Notify("Your order has been shipped");

var smsManager = new NotificationManager(new SmsNotifier());
smsManager.Notify("Your order is ready");

3. ظهرت المشكلة لما استخدمنا مكتبة خارجية

افترض إن الشركة قررت تضيف WhatsApp، واشترينا أو استخدمنا مكتبة خارجية بتوفّر الكلاس ده:

// كلاس جاي من مكتبة خارجية
public class WhatsAppService
{
    public void SendWhatsAppMessage(string text)
    {
        Console.WriteLine($"Sending WhatsApp Message: {text}");
    }
}

خد بالك من الفرق:

  • نظامنا متوقع دالة اسمها Send(string message).
  • المكتبة الخارجية بتوفّر دالة اسمها SendWhatsAppMessage(string text).

المعنى واحد تقريبًا، لكن شكل الـ Interface مختلف. عشان كده مش هينفع نمرّر WhatsAppService مباشرةً إلى NotificationManager؛ لأنه مش بيطبّق INotifier.

// ده مش هيشتغل:
var manager = new NotificationManager(new WhatsAppService());
ملحوظة: المشكلة مش إن WhatsAppService مش بيعرف يبعت رسالة. هو بيعرف، لكن نظامنا مش عارف يتعامل معاه؛ لأن طريقة النداء مختلفة.

4. الحل: نعمل Adapter

هنعمل كلاس جديد اسمه WhatsAppAdapter. الكلاس ده هيطبّق الـ Interface اللي نظامنا فاهمه INotifier، وفي نفس الوقت هيحتفظ بكائن من WhatsAppService ويستخدمه من جوّاه.

public class WhatsAppAdapter : INotifier
{
    private readonly WhatsAppService _whatsAppService;

    public WhatsAppAdapter(WhatsAppService whatsAppService)
    {
        _whatsAppService = whatsAppService;
    }

    public void Send(string message)
    {
        _whatsAppService.SendWhatsAppMessage(message);
    }
}

نفهم كل جزء ببساطة

  1. : INotifier: معناها إن الـ Adapter ملتزم بالعقد اللي نظامنا متوقعه، وبالتالي لازم يوفّر دالة Send.
  2. private readonly WhatsAppService: بنحتفظ بكائن من الكلاس الخارجي عشان نقدر نستخدمه.
  3. الـ Constructor بيستقبل كائن WhatsAppService ويحفظه في المتغير _whatsAppService.
  4. دالة Send هي الدالة اللي نظامنا بيناديها. والـ Adapter بيحوّل النداء ده لنداء المكتبة الخارجية: SendWhatsAppMessage.

ببساطة: الـ Adapter بيقول لنظامنا «ناديني بالطريقة اللي إنت متعود عليها، وأنا هتصرف وأكلم المكتبة بالطريقة اللي هي بتفهمها».

5. الاستخدام بعد إضافة الـ Adapter

var whatsAppService = new WhatsAppService();
var whatsAppAdapter = new WhatsAppAdapter(whatsAppService);

var manager = new NotificationManager(whatsAppAdapter);
manager.Notify("Your order has been shipped");

لاحظ إن NotificationManager ما اتغيرش خالص. هو لسه بيستقبل INotifier وبينادي Send. الـ Adapter هو اللي اتولى تحويل النداء.

6. الكود كامل في مكان واحد

using System;

public interface INotifier
{
    void Send(string message);
}

public class EmailNotifier : INotifier
{
    public void Send(string message)
    {
        Console.WriteLine($"Sending Email: {message}");
    }
}

public class SmsNotifier : INotifier
{
    public void Send(string message)
    {
        Console.WriteLine($"Sending SMS: {message}");
    }
}

// كلاس من مكتبة خارجية، ومش بنقدر أو مش مطلوب نعدّل فيه
public class WhatsAppService
{
    public void SendWhatsAppMessage(string text)
    {
        Console.WriteLine($"Sending WhatsApp Message: {text}");
    }
}

// الـ Adapter بيحوّل واجهة WhatsAppService لواجهة INotifier
public class WhatsAppAdapter : INotifier
{
    private readonly WhatsAppService _whatsAppService;

    public WhatsAppAdapter(WhatsAppService whatsAppService)
    {
        _whatsAppService = whatsAppService;
    }

    public void Send(string message)
    {
        _whatsAppService.SendWhatsAppMessage(message);
    }
}

public class NotificationManager
{
    private readonly INotifier _notifier;

    public NotificationManager(INotifier notifier)
    {
        _notifier = notifier;
    }

    public void Notify(string message)
    {
        _notifier.Send(message);
    }
}

public class Program
{
    public static void Main()
    {
        // Email
        var emailManager = new NotificationManager(new EmailNotifier());
        emailManager.Notify("Hello by Email");

        // SMS
        var smsManager = new NotificationManager(new SmsNotifier());
        smsManager.Notify("Hello by SMS");

        // WhatsApp باستخدام الـ Adapter
        var whatsAppService = new WhatsAppService();
        var whatsAppAdapter = new WhatsAppAdapter(whatsAppService);
        var whatsAppManager = new NotificationManager(whatsAppAdapter);
        whatsAppManager.Notify("Hello by WhatsApp");
    }
}

7. الكود بيتنفّذ إزاي؟

  1. 1 بننشئ WhatsAppService، وده الكائن اللي جاي من المكتبة الخارجية.
  2. 2 بنمرّره للـ Constructor بتاع WhatsAppAdapter، فالـ Adapter يحتفظ بيه.
  3. 3 بنمرّر الـ Adapter إلى NotificationManager. وده ينفع لأنه بيطبّق INotifier.
  4. 4 لما ننادي Notify، الـ Manager ينادي _notifier.Send(message).
  5. 5 التنفيذ يدخل دالة Send الموجودة في WhatsAppAdapter.
  6. 6 الـ Adapter ينادي SendWhatsAppMessage على كائن WhatsAppService، فتتبعت الرسالة.

الـ Output المتوقع

Sending Email: Hello by Email
Sending SMS: Hello by SMS
Sending WhatsApp Message: Hello by WhatsApp

8. ليه ما نعدّلش NotificationManager وخلاص؟

ممكن نظريًا نضيف شرط لكل نوع:

if (type == "Email")
    email.Send(message);
else if (type == "WhatsApp")
    whatsApp.SendWhatsAppMessage(message);

لكن مع كل مكتبة أو وسيلة جديدة هنفضل نعدّل في الكود الأساسي ونضيف شروط جديدة. ده بيخلّي النظام مرتبط بتفاصيل كل مكتبة، وبيصعّب الاختبار والصيانة.

باستخدام Adapter، بنعزل اختلاف المكتبة في كلاس مستقل، ونسيب الكود الأساسي يتعامل مع Interface واحد ثابت.

9. إمتى أستخدم Adapter؟

  • لما تحتاج تستخدم مكتبة خارجية وواجهتها مختلفة عن الواجهة الموجودة في مشروعك.
  • لما يكون عندك كود قديم (Legacy Code) وعايز توصّله بنظام جديد من غير ما تغيّر الكود القديم.
  • لما تتعامل مع أكثر من مزوّد لخدمة واحدة، وكل مزوّد عنده أسماء دوال أو طريقة استخدام مختلفة.
  • لما تحب تخلي تفاصيل التكامل مع خدمة خارجية معزولة بدل ما تنتشر في كل أجزاء المشروع.

10. الفرق بين Adapter و Decorator

Adapter PatternDecorator Pattern
بيغيّر أو يكيّف شكل الواجهة عشان كودين مش متوافقين يقدروا يتعاملوا.بيضيف سلوك أو مسؤولية لكائن موجود من غير ما يغيّر الكلاس الأصلي.
مثال: عندي SendWhatsAppMessage والنظام محتاج Send.مثال: أضيف Logging أو Encryption حوالين خدمة الإرسال.
الهدف الأساسي: التوافق بين واجهتين مختلفتين.الهدف الأساسي: إضافة سلوك بشكل مرن وقابل للتركيب.

احفظها كده: Adapter يخلّي حاجتين مش فاهمين بعض يشتغلوا مع بعض. Decorator يزوّد إمكانيات كائن موجود.

11. سؤال تتأكد بيه إنك فهمت

عندك النظام بتاعك متوقع:

public interface INotifier
{
    void Send(string message);
}

وجالك كلاس من مكتبة خارجية بالشكل ده:

public class ExternalSmsLibrary
{
    public void SendSmsMessage(string phoneNumber, string text)
    {
        Console.WriteLine($"To: {phoneNumber}, Message: {text}");
    }
}

المطلوب: إزاي تخلي NotificationManager يستخدم المكتبة دي من غير ما تغيّر NotificationManager؟

فكّر في الحل: هتعمل SmsAdapter : INotifier، وتخليه يستقبل ExternalSmsLibrary في الـ Constructor. وفي دالة Send(string message) هتنادي SendSmsMessage(phoneNumber, message). محتاج كمان تحدد رقم التليفون من إعدادات أو بيانات مناسبة، لأن المكتبة بتطلبه.

الخلاصة

  1. عندك نظام بيتعامل مع Interface محدد.
  2. لقيت كلاس أو مكتبة بتعمل نفس الوظيفة لكن بواجهة مختلفة.
  3. بتنشئ Adapter يطبّق الـ Interface اللي نظامك محتاجه.
  4. الـ Adapter يحتفظ بالكائن الخارجي وينادي دواله بالطريقة المناسبة.
  5. النظام الأساسي يفضل يتعامل مع الـ Interface المعتاد من غير ما يعرف تفاصيل المكتبة.
